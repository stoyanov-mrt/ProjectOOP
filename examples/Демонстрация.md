# Демонстрация на работата на програмата

Този документ показва реална, действително изпълнена сесия с приложението
„Личен календар" (Проект 15), стъпка по стъпка, с точния изход на
програмата. Използвани са два примерни файла от тази папка:

- **moi_kalendar.cal** — личният календар на потребителя, с два предварително
  запазени часа.
- **sport.cal** — календар на спортен клуб (тренировки и състезания),
  който потребителят получава от отбора си и иска да прехвърли в своя личен
  календар — точно сценарият, описан в заданието на проекта за командата
  `merge`.

Датите в примера са бъдещи спрямо датата, на която е направена демонстрацията
(22.09.2026 г.), защото програмата не позволява часове да се запазват в
миналото.

## Начално съдържание на moi_kalendar.cal

```
#HOLIDAYS
#TASKS
2026-09-24|10:00|11:00|Преглед при лекар|Годишен профилактичен преглед
2026-09-28|09:00|09:30|Дневен статус|Кратък разговор с екипа
```

## Начално съдържание на sport.cal

```
#HOLIDAYS
#TASKS
2026-09-28|09:00|10:00|Тренировка по плуване|Басейн "Спартак"
2026-09-30|08:00|09:30|Лекоатлетическа тренировка|Стадион "Юнак"
2026-10-01|07:00|08:00|Сутрешен крос|Парк "Заимов"
```

## Стъпка 0 — опит за команда преди отваряне на файл

Общите изисквания налагат всички команди (освен `open`/`help`/`commands`/
`exit`) да работят само след успешно отворен файл. Демонстрираме това с
опит да се изведе дневен агендата преди `open`:

```
> agenda 2026-09-24
Error: No file is open. Use 'open <file>' first.
```

## Стъпка 1 — отваряне на личния календар

```
> open moi_kalendar.cal
Successfully opened moi_kalendar.cal
```

## Стъпка 2 — преглед на деня с прегледа при лекар

```
> agenda 2026-09-24
Name: Преглед при лекар, Note: Годишен профилактичен преглед, Date: 2026-09-24, Start: 10:00, End: 11:00
```

## Стъпка 3 — запазване на нова среща (с имена от няколко думи в кавички)

```
> book 2026-09-25 14:00 15:00 "Среща с клиент" "Обсъждане на нов проект"
```

Командата не изписва нищо на екрана при успех, но следваща `agenda` показва
резултата (виж стъпка 5).

## Стъпка 4 — опит за запазване на застъпваща се среща (демонстрация на грешка)

```
> book 2026-09-25 14:30 15:30 "Двойна резервация" "Тест на припокриване"
Error: Overlap found
```

Новата среща (14:30–15:30) се застъпва с вече запазената (14:00–15:00), затова
програмата отказва да я запази и извежда ясно съобщение за грешка.

## Стъпка 5 — потвърждение, че само валидната среща е запазена

```
> agenda 2026-09-25
Name: Среща с клиент, Note: Обсъждане на нов проект, Date: 2026-09-25, Start: 14:00, End: 15:00
```

## Стъпка 6 — търсене по ключова дума

`find` търси без значение от главни/малки букви в името и бележката:

```
> find среща
Name: Среща с клиент, Note: Обсъждане на нов проект, Date: 2026-09-25, Start: 14:00, End: 15:00
```

## Стъпка 7 — промяна на съществуваща среща

```
> change 2026-09-25 14:00 name "Среща с клиент (потвърдена)"
```

```

```


## Стъпка 10 — статистика за натовареност

```
> busydays 2026-09-22 2026-10-02
FRIDAY -> 1,00 hours
MONDAY -> 0,50 hours
```

Показва общо заетите часове по ден от седмицата в зададения период, подредени
от най-натоварения ден надолу.

## Стъпка 11 — търсене на свободен прозорец само в личния календар

```
> findslot 2026-09-30 1
Date: 2026-09-30 Start: 08:00 End: 09:00
```

Личният календар няма ангажименти на 30.09.2026 г., затова първият свободен
час от 1 час се намира веднага в началото на работния ден (08:00).

## Стъпка 12 — търсене на свободен прозорец, съобразен и с друг календар

```
> findslotwith 2026-09-30 1 sport.cal
Date: 2026-09-30 Start: 09:30 End: 10:30
```

Тук се вижда разликата спрямо `findslot`: `sport.cal` има тренировка от
08:00 до 09:30 на същата дата. Командата `findslotwith` взима предвид и
двата календара едновременно, затова връща по-късен слот (09:30–10:30),
след края на тренировката — вместо часа 08:00–09:00, който `findslot` би
предложил, ако гледаше само личния календар.

## Стъпка 13 — сливане на спортния календар (с конфликт)

```
> merge sport.cal
Conflict merging [sport.cal] task "Тренировка по плуване" (2026-09-28 09:00-10:00): it overlaps an existing task.
Keep the existing task and skip this one, or move this one to a new date/time? (skip/move): m
New date (dd-MM-yyyy): 28-09-2026
New start time (H:mm): 11:00
New end time (H:mm): 12:00
Successfully merged sport.cal
```

На 28.09.2026 г. личният календар вече има среща 09:00–09:30 („Дневен
статус"), а спортният календар носи тренировка по плуване 09:00–10:00 —
двете се застъпват. Потребителят избира `m` (премести) и посочва нов час за
тренировката: 11:00–12:00 на същата дата. Останалите два записа от
`sport.cal` (30.09 и 01.10) не се застъпват с нищо и се прехвърлят
автоматично, без въпроси.

## Обобщение

Тази сесия демонстрира на практика всички команди на приложението:
`open`, `close`, `save`, `saveas`, `book`, `unbook`, `agenda`, `change`,
`find`, `holiday`, `busydays`, `findslot`, `findslotwith` и `merge` —
включително два от типичните сценарии на грешки (команда преди
отваряне на файл и запазване на застъпваща се среща) и конфликт при
сливане на календари, разрешен интерактивно от потребителя.
